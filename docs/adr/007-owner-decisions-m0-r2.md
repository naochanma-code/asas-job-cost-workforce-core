# ADR-007 — คำตอบ Owner และต้นแบบ Milestone 0 รอบ 2

วันที่ 2026-09-21 · Decision owner: โอ๋ · สถานะ Accepted เฉพาะคำตอบที่ระบุด้านล่าง

แหล่งตัดสินใจคือคำตอบ Owner ใน task นี้ต่อ Q-01–07 และข้อสังเกตว่าไม่มีอัปโหลดรูป/ประเภทรายจ่ายไม่ครบ บันทึกเป็นข้อกำหนดกลาง v2.3 โดยไม่เริ่ม Production Application การอนุมัติกติกาไม่ใช่การผ่าน UAT ทั้ง milestone

## ยืนยันแล้ว

1. ADMIN/PM เห็นจำนวนคน วันเข้างาน จำนวนวันทำงาน และชั่วโมง OT ตามขอบเขตงานเท่านั้น **ไม่เห็นเงินทุกประเภท**: งบ ค่าใช้จ่าย ค่าแรง Payroll กำไร ยอดรวม เปอร์เซ็นต์ใช้เงิน และข้อมูลที่คำนวณย้อนกลับได้ OWNER เห็นเงินและจัดการการเงิน
2. OWNER รองรับหลายบัญชีสำหรับหุ้นส่วน 3 คน บัญชีแยกกัน role เดียวกัน ไม่ใช่บัญชีร่วม ไม่ผูก unique constraint กับ role OWNER ทุกการเปลี่ยนมี actor ID ผู้ทำจริง; ไม่เพิ่มกติกาว่าต้องอนุมัติพร้อมกัน 3 คน เพราะ Owner ไม่ได้ขอ และต้องป้องกันอนุมัติ/บันทึกจ่ายซ้ำเมื่อใช้พร้อมกัน
3. Project เป็นหลัก ไม่มี Site/Job ก็ทำงานได้ครบ; รองรับเพิ่มงานย่อยภายหลัง ไม่บังคับสร้างงานย่อย
4. OT กรอกวันที่อ้างอิงและจำนวนชั่วโมง ลงย้อนหลังได้ เช่นวันที่ 21 กันยายน 8 ชั่วโมง แม้ทำต่อถึงวันที่ 22 ให้คิดตามวันที่ 21 ทั้งรายการ ไม่แยกเที่ยงคืน ไม่บังคับเวลาเริ่ม/จบ Rate/holiday/period อ้างวันที่ที่เลือก; การลงหลังปิดข้อมูลยังเข้า late adjustment ไม่เปลี่ยนรอบเดิมเงียบ
5. ทำสอง Project ในวันเดียวแบ่ง Project ละ 0.5 วัน รวม 1 วัน ค่าแรงและค่ากินแบ่งตามสัดส่วนเดิม (ค่ากิน60+60=120 จาก accepted baseline); จำนวนวันที่เข้างานจริงของคนเดียววันเดียวเท่ากับ1 ไม่ใช่2 และจำนวนคนใช้ distinct employee
6. รายงานเงินรายเดือนสำหรับ OWNER และนำบิล/ใบเสร็จ/สลิปของ expense ออกเป็น folder ทั้งเดือนได้ ใช้ ZIP ที่แตกแล้วเป็น folder ตามเดือน/Project/Job ที่มีจริง; ยังใช้ SMEMOVE เป็นโปรแกรมบัญชีแยก ไม่เชื่อม SMEMOVE API ใน M0
7. Owner จะเตรียมการทดลองจริงภายหลัง ไม่ต้องรอข้อมูล pilot เพื่อแก้ต้นแบบรอบนี้

## ผลต่อ workflow/permission

- ADMIN ตรวจและอนุมัติ Work/OT ต่อได้; PM ดูข้อมูลกำลังคนใน Project ที่รับผิดชอบ ตรวจเวลาได้เมื่อ policy เปิด แต่ไม่มีสิทธิ์เงิน
- การตรวจ/แก้ยอด/อนุมัติ Expense และ Budget ย้ายไป OWNER เพื่อทำตามข้อห้ามเห็นเงินของ ADMIN/PM (เป็นผลที่จำเป็นของคำสั่ง ไม่สร้างช่องให้ Admin เห็นยอดผ่านภาพบิล)
- TECH ยังคงกรอกยอดและแนบบิลของตนตาม flow เดิม และเห็นของตนใน private view เท่านั้น; คำสั่งปิดเงินของ ADMIN/PM ไม่ได้ยกเลิกการส่งค่าใช้จ่ายของช่าง
- ADMIN/PM ไม่ได้ raw description/filename/รูปบิล/สลิป/ลิงก์ดาวน์โหลด/manifest เพราะข้อความและรูปอาจมีราคา แม้ JSON amount ถูกซ่อนแล้ว; อนุญาตแค่จำนวนรายการ/สถานะที่ไม่เผยเงินหากจำเป็น
- Payroll payment proof ยังคง Owner-only แยกจาก expense receipts แต่สลิปค่าใช้จ่ายปกติอยู่ใน monthly expense folder

## สิ่งที่ยังไม่ได้ยืนยัน

- OT เศษชั่วโมงที่เล็กกว่า 0.5 และ OT ไม่มี Work Entry: ไม่ถามซ้ำเรื่องลงย้อนหลัง/ข้ามคืนที่ตอบแล้ว; ต้นแบบรับชั่วโมงเต็ม/ครึ่งชั่วโมงตามตัวอย่างเดิม ไม่ใช่การยืนยันหน่วยต่ำสุดสำหรับระบบจริง
- Q-05 Owner ยืนยันสิทธิ์เงิน ไม่ได้ยืนยันรายละเอียดสูตร Job budget allocation; การแบ่งงบ/เพิ่มงบยังเป็น proposal เดิมสำหรับ Owner เท่านั้น
- ระยะเก็บหลักฐานจริงยังไม่ยืนยัน การใช้ SMEMOVE ไม่ได้อนุญาตให้ลบบิลหรือรับรอง retention 7 ปี; เดือนใช้ expense_date เป็นค่าเสนอสำหรับต้นแบบ

## ต้นแบบและ validation

ต้นแบบ local เพิ่ม input เลือกภาพ/PDF จริงจากเครื่อง 1–5 ไฟล์ ≤10MB/ไฟล์ ตรวจชนิดจาก bytes, แสดงภาพ/ลิงก์ PDF, เปลี่ยน/ลบก่อนยืนยัน และ Owner download ZIP เก็บ folder ทั้งเดือนจากไฟล์ที่เลือกจริง ไม่มี upload server, network, browser persistence หรือ cloud storage Refresh ล้าง session ไม่ใส่รูปจริงใน Git

ประเภทรายจ่ายที่เลือกได้ครบ9หมวดใน MASTER: FUEL/TRAVEL/ACCOMMODATION/MEAL/MATERIAL_DIRECT/HARDWARE_DIRECT/SUBCONTRACTOR/TRANSPORT/OTHER; LABOR/OT คำนวณจากเวลา ไม่เปิดให้ส่ง expense ซ้ำ ค่าอาหารตามบิลแยกจากค่ากินรายวันและ Owner ตรวจการเบิกซ้ำ

ต้องตรวจ ADMIN/PM ทุกหน้าไม่มีตัวเลขเงิน/receipt, OWNER ทั้ง3ทำงานได้, OT 21→22 ยังอยู่วันที่21, AM A+PM Bรวม1day/meal120, ZIPมี bytes ของไฟล์ตรงต้นฉบับและชื่อ path ไม่ใช้ชื่อไฟล์ผู้ใช้ พร้อม status/changelog/test evidence ยังไม่อ้าง server permission/LINE/UAT จริง

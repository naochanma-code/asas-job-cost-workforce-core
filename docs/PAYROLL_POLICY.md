# PAYROLL POLICY — Release แรก

สถานะ: Accepted baseline  
เจ้าของนโยบาย: Owner / ASAS IT

## รอบและกำหนดจ่าย

- รอบข้อมูล: วันที่ 1 ถึงวันสุดท้ายของเดือนตามเวลา Asia/Bangkok
- กำหนดโอน: ไม่เกินวันที่ 1 ของเดือนถัดไป
- วันที่ 1 เป็นวันหยุดให้ใช้ electronic transfer ภายในวันที่ 1 เป็นค่าเริ่มต้น

## ขั้นตอนปิดรอบ

1. ช่างส่งวันทำงานและ OT ของวันสุดท้ายภายในวันนั้น
2. Admin ตรวจวันเต็ม/ครึ่งวัน, วันหยุด, OT และรายการผิดปกติให้เสร็จไม่เกิน 10:00 น. วันที่ 1
3. Admin กด `ส่งให้ Owner ตรวจ` โดยระบบไม่แสดงหรือส่งอัตราค่าจ้างและยอดเงินให้ Admin
4. ระบบคำนวณจาก rate/policy version ที่มีผล
5. Owner ตรวจอัตรารายวัน รายการเพิ่ม/หัก ยอดรวม และอนุมัติ/lock
6. Owner โอนและบันทึกวันเวลา/หลักฐานการจ่ายภายในวันที่ 1

## สูตร Release แรก

- วันปกติเต็มวัน: อัตรารายวัน × 1.0
- ครึ่งวัน: อัตรารายวัน × 0.5
- วันอาทิตย์/วันหยุดที่มาทำงาน: อัตรารายวัน × 2 × สัดส่วนวัน
- ค่ากิน: เต็มวัน 120 บาท, ครึ่งวัน 60 บาท เฉพาะวันที่มาทำงาน
- OT วันปกติ: `(อัตรารายวัน ÷ 8) × 2 × ชั่วโมง`
- OT วันหยุด: `(อัตรารายวัน ÷ 8) × 3 × ชั่วโมง`
- ยังไม่คำนวณภาษีและประกันสังคมอัตโนมัติ

## สิทธิ์

- Admin: กรอก/ตรวจวันและชั่วโมง เห็นสถานะและข้อผิดปกติ แต่ไม่เห็น rate หรือยอดเงินรายคน/ยอดรวม
- Owner: กรอกและแก้ rate, รายการเพิ่ม/หัก, เห็นยอด, อนุมัติ, lock และบันทึกจ่าย
- การป้องกันต้องอยู่ที่ API และ export ไม่ใช่เพียงซ่อนหน้าจอ

## ข้อมูลมาช้าและการแก้ย้อนหลัง

- รายการหลัง `TIME_REVIEWED` ต้องเป็น `LATE_ADJUSTMENT`
- ก่อนจ่าย Owner อาจ reopen พร้อมเหตุผลและสร้าง revision
- หลังจ่ายให้ปรับรอบถัดไปเป็นค่าเริ่มต้น เว้นแต่ Owner อนุมัติ correction payment แยก
- ห้ามแก้หรือลบ Payroll Ledger ที่อนุมัติแล้วแบบเงียบ

## Acceptance cases ขั้นต่ำ

- วันที่สุดท้ายของเดือนรวมในรอบเดียวกัน
- Admin ตรวจได้โดย payload ไม่มีข้อมูลเงิน
- Owner ปิดและบันทึกจ่ายภายในวันที่ 1
- วันหยุดเต็ม/ครึ่งวันและ OT ใช้สูตรถูกต้อง
- รายการมาช้าไม่เปลี่ยนยอดเดิมและมี audit ครบ
- Cost Ledger และ Payroll Ledger ไม่ถูกนำมารวมซ้ำ
